# School21 OpenAPI: подтверждённые возможности

Проверено 10.10.2026 по [официальной спецификации](https://platform.21-school.ru/services/21-school/api/swagger)
и авторизованным запросам клиента. Публичный контракт: 25 путей, 25 операций,
41 DTO. [Матрица ресурсов](resources.md) покрывает все опубликованные маршруты.
Это не описание всех внутренних API веб-платформы.

## GET и POST

- Все 25 ресурсных операций OpenAPI — **GET**, то есть чтение.
- Получение и обновление JWT — **POST** в официальный Keycloak token endpoint,
  `client_id=s21-open-api`, form-urlencoded password/refresh grant.
- В локальном кабинете `/api/login`, `/api/demo`, `/api/logout` также POST,
  но это управление локальной сессией, не изменение учебных данных School21.
- Сдача проектов, запись на проверки/мероприятия и изменение профиля через этот
  публичный OpenAPI не описаны. Нельзя обещать их поддержку на основании GET.

## Дедлайн, длительность и даты

| Поле | Что оно означает |
| --- | --- |
| `durationHours` в Project/Course | Длительность из каталога, в часах |
| `completionDateTime` у проекта/курса участника | Дата последнего завершения; может быть null |
| `startDateTime`, `endDateTime` мероприятия | Начало и окончание мероприятия |
| `accrualDateTime` | Начисление XP |
| `receiptDateTime` | Получение значка |

**Персонального дедлайна и начала текущей попытки в опубликованных моделях нет.**
Нельзя вычислять срок сдачи, прибавляя `durationHours` к `completionDateTime`,
текущей дате или произвольной дате из истории XP. Реальные ответы изученных
проектов/курсов совпали с этими моделями и не добавили deadline/due/expiry.
Персональный срок может существовать в интерфейсе платформы или другом API —
эта проверка не доказывает его отсутствие там.

## Статусы проектов

| Код API | Смысл |
| --- | --- |
| `ASSIGNED` | Назначен; это не завершённая неуспешная проверка |
| `REGISTERED` | Зарегистрирован |
| `IN_PROGRESS` | В работе |
| `IN_REVIEWS` | На проверке |
| `ACCEPTED` | Принят |
| `FAILED` | Проверка не пройдена |

`FAILED` не означает «все проекты, которые ещё не приняты»: назначенные,
зарегистрированные, текущие и находящиеся на проверке — отдельные статусы.
Значение фильтра передаётся серверу, смена статуса сбрасывает страницу списка.

## Дерево и условия старта

Граф содержит группы, проекты/курсы и связи. Связь показывает зависимость учебного
маршрута, но сама по себе не доказывает, что участнику уже разрешён старт.
Подробности `/projects/{id}` и `/courses/{id}` содержат `startConditions`:
группы правил, поля, операторы, значения и логические AND/OR.

Условия могут требовать данных, которых OpenAPI не предоставляет (например,
сколько дней участник находится на курсе). Поэтому итог «можно начать» требует
сопоставления известных данных с правилами и честного обозначения неизвестного.
`ASSIGNED` также не является доказательством выполнения всех условий допуска.

## Ограничения живой проверки

Вход и защищённое чтение настоящего аккаунта подтвердились. Каждый из 25
маршрутов был вызван с подходящими параметрами/ID. Большинство вернули данные;
workstation при отсутствии места вернул HTTP200 с пустым телом — клиент
обрабатывает этот наблюдаемый случай как отсутствие назначенного места.
Другие пустые успешные ответы не маскируются. Отдельные каталоговые ID вернули
500; это не подменяется пустым результатом или фиктивными данными.
Личные снимки ответов и учётные данные не входят в публичный репозиторий.
